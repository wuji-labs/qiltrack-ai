## 5. Lessons Learned (经验教训)

### 5.1 成功经验

1. **外科手术式替换的有效性**
   - 仅修改 3 个文件，净增 111 行代码
   - 零破坏性变更，所有中间功能区完整保留
   - **可重复性**：此模式可应用于 Phase 2/3

2. **Interface-first 设计**
   - 先扩展 NavigationProps，再实现功能
   - 类型安全确保集成正确性
   - **最佳实践**：未来组件迁移都应遵循此模式

3. **Git Diff 作为验证工具**
   - 通过 diff 快速确认未触碰中间区
   - 变更统计一目了然（3 files, +111 lines）
   - **流程化**：可作为 PR review checklist

### 5.2 遇到的挑战

1. **预存在构建错误的干扰**
   - 问题：19 lint errors + 3 build errors 让人难以辨别新增问题
   - 解决：使用 `git diff --name-only` 聚焦修改文件
   - **改进建议**：建立 baseline error list，新增 error 才需修复

2. **Sparse Checkout 的隐藏陷阱**
   - 问题：Admin components 缺失导致构建失败
   - 解决：文档化 sparse checkout 配置
   - **改进建议**：提供 `scripts/setup-sparse-checkout.sh` 自动化脚本

### 5.3 未来优化方向

1. **自动化测试覆盖**
   - 当前：手动验证 responsive + 功能测试
   - 目标：Playwright E2E 测试覆盖核心流程
   - 优先级：P1（Phase 3 考虑）

2. **组件 Storybook**
   - 当前：组件孤立性难以验证
   - 目标：Navigation + HeroNew Storybook stories
   - 优先级：P2（可选）

3. **Performance Budgets**
   - 当前：未监控页面性能影响
   - 目标：Lighthouse CI 集成，设置性能阈值
   - 优先级：P1（Phase 3 考虑）
